# Схема данных

Три уровня: frontmatter статьи, запись чанка, манифест корпуса. Все они генерируются
скриптами из `scripts/` и проверяются `scripts/validate.py`.

## Frontmatter статьи (`code/ru/**/st-NNN.md`)

| Поле | Тип | Смысл |
|---|---|---|
| `doc_id` | строка | идентификатор документа, `kz-tax-code-2025` |
| `edition_id` | строка | редакция источника, `nalogovyy-kodeks-2025` |
| `article_uid` | строка | стабильный ключ статьи, `kz-tax-code-2025/ru/st-190` |
| `article` | строка | номер статьи как в кодексе (`"190"`) |
| `article_label` | строка | «Статья 190» — готовая подпись для цитаты |
| `heading` | строка | заголовок статьи без слова «Статья N» |
| `lang` | строка | язык текста (`ru`) |
| `part` | строка | «Общая часть» / «Особенная часть» |
| `razdel`, `razdel_title` | число, строка/null | номер и название раздела; `null` — в источнике их нет |
| `glava`, `glava_title` | число, строка | номер и название главы |
| `paragraf`, `paragraf_title` | число/null, строка/null | параграф внутри главы, если он есть |
| `path` | строка | человекочитаемый путь «часть > раздел > глава > параграф > статья» |
| `status` | строка | `active` — норма в корпусе; `source_empty` — источник отдал пустое тело |
| `revision_id` | строка | идентификатор редакции корпуса (`2026-01-01`) |
| `effective_from` | дата | дата введения статьи в действие (по статье 848) |
| `effective_to` | дата/null | дата утраты силы; `null` — не ограничена |
| `effective_note` | строка | только когда часть статьи вводится в действие отдельным сроком |
| `point_count`, `paragraph_count` | число | количество нумерованных пунктов и абзацев |
| `cross_references` | список строк | номера статей, на которые ссылается текст (без самой себя) |
| `source_name`, `source_url` | строка | откуда взят текст и прямая ссылка на статью |
| `source_article_id` | строка | идентификатор статьи в источнике |
| `source_updated_at`, `retrieved_at` | дата, метка времени | дата обновления в источнике и момент выгрузки |
| `source_text_sha256` | строка | хэш текста, посчитанный при выгрузке из источника |
| `text_sha256` | строка | хэш нормализованного текста в этом файле; его проверяет CI |
| `tags` | список строк | теги для Obsidian и фильтров |
| `razdel_title_missing_in_source`, `razdel_note` | флаг, строка | раздел без названия в источнике |
| `duplicate_number_rank` | число | порядок среди статей с одинаковым номером (случай статьи 419) |
| `source_title_mismatch`, `source_api_title` | флаг, строка | заголовок API источника расходится с оглавлением |
| `source_body_empty` | флаг | источник вернул статью с пустым текстом |

Тело файла: заголовок `# Статья N. …`, блок-справка с путём и ссылкой на источник, затем текст.
Каждый нумерованный пункт начинается якорем `<a id="p-N"></a>`, поэтому ссылка вида
`code/ru/.../st-190.md#p-3` ведёт прямо в пункт 3.

**Что означает пара хэшей.** `source_text_sha256` фиксирует, что пришло из источника;
`text_sha256` — что лежит в этом файле после нормализации (снятие табуляций и мягких переносов,
склейка абзаца в одну строку). Правка текста статьи без пересборки ломает `text_sha256`,
и CI это отлавливает — см. проверку V-04.

## Запись чанка (`data/chunks.jsonl`, одна строка — один JSON)

| Поле | Смысл |
|---|---|
| `chunk_id` | `kz-tax-code-2025/ru/st-190/p-3`; для статей без нумерации — `/full` |
| `parent_id` | `article_uid` статьи, к которой относится чанк |
| `point`, `anchor` | номер пункта и якорь в Markdown-файле |
| `context_header` | контекстный префикс: статья, раздел, глава, пункт, редакция |
| `text` | текст пункта целиком, включая непронумерованные абзацы этого пункта |
| `path`, `razdel`, `glava`, `paragraf`, `heading` | место в структуре — для фильтров |
| `revision_id`, `effective_from`, `effective_to`, `effective_note` | временнáя привязка нормы |
| `siblings` | соседние пункты той же статьи |
| `cross_references` | номера статей, упомянутых в статье |
| `file`, `source_url` | путь в репозитории и ссылка на источник |
| `text_sha256` | хэш текста чанка |
| `approx_tokens` | грубая оценка длины (символы ÷ 3.2), а не результат токенизатора |

Разбиение — **структурное**: граница чанка совпадает с границей пункта статьи, а не с окном
из N символов. Пункт длиннее 6 000 символов режется по абзацам, и тогда к `chunk_id`
добавляется суффикс `--2`, `--3`.

`context_header` предназначен для подстановки перед `text` при индексации — короткий префикс
о месте фрагмента в документе заметно снижает промахи retrieval.

## Манифест (`manifest.json`)

`doc_id`, `edition_id`, `revision_id`, `effective_from`, `source` (имя, URL, момент выгрузки,
хэш оглавления и хэш манифеста исходной выгрузки), `counts` (статьи, разделы, главы, дубликаты
номеров, пустые тела), `anomalies` (особенности источника) и `files` — запись на каждую статью
с путём, хэшами текста и файла, размером и датой введения в действие.

## Инварианты, которые держит CI

`scripts/validate.py` (15 проверок, ненулевой код возврата = публиковать нельзя):
совпадение манифеста с деревом файлов, обязательные поля frontmatter, оба хэша, отсутствие CRLF
и символов замены, разрешимость локальных ссылок, уникальность `article_uid`, номера 1–848 без
пропусков, дубликаты только там, где они есть в источнике, перекрёстные ссылки только на
существующие статьи, полнота `index.md`, консистентность чанков и покрытие ими каждой непустой
статьи, существование статей, упомянутых в эталонных вопросах.
