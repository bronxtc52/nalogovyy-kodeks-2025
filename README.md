## Подключить к LLM и начать задавать вопросы

Четыре способа, от самого простого к самому гибкому. Все работают на стандартной
библиотеке Python 3.11+ — ни `pip install`, ни внешних сервисов не требуется.

### 1. Coding-агент читает репозиторий как базу знаний (0 минут настройки)

Самый быстрый путь: клонировать и открыть каталог в Claude Code, Codex или другом
агенте с доступом к файлам. В корне лежит [`CLAUDE.md`](CLAUDE.md) — инструкция для агента:
где искать, как ссылаться на пункт и почему нельзя отвечать по памяти. Агент прочитает её сам.

```bash
git clone https://github.com/bronxtc52/nalogovyy-kodeks-2025.git
cd nalogovyy-kodeks-2025
claude          # или codex, или откройте каталог в IDE с агентом
```

Дальше — обычные вопросы:

> — Что говорит кодекс о сроках выписки счетов-фактур? Дай ссылки на пункты.
>
> — Сравни порядок исчисления КПН и ИПН: где нормы расходятся?
>
> — Какие статьи ссылаются на статью 190?

Полезные команды, если хочется искать руками:

```bash
grep -rl '^article: "190"' code/ru          # файл статьи по номеру
grep -ril "счет-фактура" code/ru | head     # статьи по слову
grep -n "Статья 5[0-9][0-9]\." index.md     # что вообще есть в этом диапазоне
```

### 2. Готовый ассистент в одну команду: `scripts/ask.py`

Скрипт делает полный цикл RAG: ищет нормы по вопросу, собирает их в контекст и просит
модель ответить со ссылками на статью и пункт.

```bash
python3 scripts/build_sqlite.py                              # один раз: индекс поиска
export ANTHROPIC_API_KEY=...                                 # ключ только из окружения
python3 scripts/ask.py "Кто обязан встать на регистрационный учёт по НДС?"
```

Что он выведет: сначала список найденных норм со ссылками на источник, затем ответ модели.
**Без ключа скрипт работает как «сухой прогон»** — покажет найденные фрагменты и то, что ушло бы
в модель. Это же режим для отладки поиска:

```bash
python3 scripts/ask.py --dry-run --top-k 12 "срок исковой давности"
python3 scripts/ask.py --model claude-sonnet-5 "Что такое налоговый регистр?"
```

Системный промпт внутри скрипта задаёт три правила, которые стоит сохранить в любом своём
ассистенте: ссылаться на статью и пункт, честно говорить «в предоставленных нормах ответа нет»
и называть особый срок введения нормы, если он есть.

### 3. Свой RAG: `chunks.jsonl` подключается к любому стеку

`data/chunks.jsonl` — одна строка на пункт статьи, всё нужное уже в полях:

```python
import json

chunks = [json.loads(line) for line in open("data/chunks.jsonl", encoding="utf-8")]
c = chunks[100]
c["text"]            # текст пункта
c["context_header"]  # «Статья 12 НК РК (Вознаграждение), раздел 1 …, пункт 2, редакция с 2026-01-01»
c["path"]            # место в структуре кодекса
c["article"], c["point"], c["anchor"]   # для цитаты со ссылкой
c["effective_from"]  # для временнóй фильтрации
c["source_url"]      # проверяемая ссылка на источник
```

Две вещи, которые стоит сделать при индексации:

- **Класть `context_header` перед `text`** — короткий префикс о месте фрагмента в кодексе
  заметно снижает промахи поиска, потому что в самом пункте часто нет слов «НДС» или
  «корпоративный подоходный налог», хотя он именно о них.
- **Фильтровать по `effective_from`**, если ассистент отвечает на вопросы «а как было/будет».
  Иначе ответ смешает нормы с разными сроками введения.

Локальный гибридный поиск без внешних сервисов уже собран: `dist/tax.sqlite` — обычный
SQLite с FTS5, работает из любого языка.

```bash
sqlite3 dist/tax.sqlite "
  SELECT c.article_label, c.point, snippet(chunks_fts, 1, '[', ']', '…', 10)
  FROM chunks_fts JOIN chunks c ON c.rowid = chunks_fts.rowid
  WHERE chunks_fts MATCH 'счет-фактура AND экспедитор'
  ORDER BY bm25(chunks_fts) LIMIT 5;"
```

### 4. Веб-агенты и чат-интерфейсы: `llms.txt`

В корне лежит [`llms.txt`](llms.txt) по спецификации llmstxt.org: короткая точка входа со
ссылками на оглавление, схему и все 23 раздела. Агент, умеющий ходить по ссылкам, дотянет
нужную статью сам. Ссылки в файле — на «сырой» Markdown, без HTML-обвязки.

### 5. Как хранилище Obsidian

Откройте каталог репозитория как vault: ссылки между статьями, callout-блоки и теги уже
расставлены, оглавление — в `index.md`. Блок `USER_CONTENT` в статьях исходной выгрузки
задумывался под личные заметки; здесь его роль играет обычный Markdown под текстом статьи.

## Примеры вопросов и что на них находится

Проверено на собранном индексе (`scripts/ask.py --dry-run`). Полезно как проверка, что
подключение работает, и как ориентир, какие формулировки корпус понимает хорошо.

| Вопрос | Что находится |
|---|---|
| «Что кодекс понимает под роялти?» | статья 7 — определение целиком |
| «Что такое налоговый регистр?» | статья 205, пункт 1 (определение) и пункты про его составление |
| «Какая ставка НДС?» | статья 503 «Ставки налога на добавленную стоимость» |
| «Какие ставки корпоративного подоходного налога?» | статья 357 (раздел 5) — заголовок в источнике просто «Ставки налога», поэтому запрос со словом «корпоративный» лексический поиск уводит; помогает уточнение «раздел 5» или поиск по главе |
| «Срок исковой давности по налоговому обязательству» | статья 65 |
| «Условия упрощённой декларации» | статья 723 |
| «Когда кодекс вводится в действие?» | статья 848 — включая перечень норм с отложенным сроком |
| «Что является объектом обложения налогом на имущество?» | статьи 590 и 599 — для юридических и для физических лиц |

Четвёртая строка — не дефект корпуса, а свойство лексического поиска: в кодексе десятки
статей с заголовком «Ставки налога», и различает их только раздел. Это ровно тот случай,
который лечится эмбеддингами (версия 0.2.0) или фильтром по `razdel` при поиске.

## Что можно построить вокруг этого репозитория

Корпус даёт то, чего обычно не хватает для налоговых ассистентов: проверяемую цитату до пункта,
дату введения нормы и стабильные идентификаторы. Ниже — идеи с указанием, что именно из репозитория
использует каждая и где будут грабли.

**1. Telegram-бот «спроси у кодекса» для бухгалтера.** `scripts/ask.py` — уже готовое ядро:
допишите приём сообщения и отправку ответа. Использует `tax.sqlite` и `chunks.jsonl`.
Грабли: длинные ответы упираются в лимит сообщения — режьте по абзацам, а не по символам;
и обязательно выводите дисклеймер о неофициальности при первом обращении.

**2. MCP-сервер для Claude Code и других агентов.** Инструменты `search_articles(query, razdel?)`,
`get_article(article, on_date?)`, `diff_revisions(article, from, to)`. Подключается одной строкой
в конфиге — самый короткий путь дать корпус любому агенту без клонирования. Запланировано как
версия 0.3.0, см. [issue #3](https://github.com/bronxtc52/nalogovyy-kodeks-2025/issues/3).

**3. Ассистент внутри учётной системы.** Сотрудник выделяет операцию — ассистент показывает
нормы, которые её регулируют. Здесь особенно важны `cross_references`: от одной статьи можно
дотянуть связанные, не подмешивая в контекст весь раздел.

**4. Мониторинг изменений кодекса.** Повторный экспорт → пересборка → `git diff` покажет
буквальное изменение нормы, а не «файл поменялся». Отсюда — дайджест «что изменилось в НК
за неделю» с точностью до пункта. Механика тегов `revision/<дата>` описана ниже.

**5. Проверка внутренних документов на соответствие кодексу.** Учётная политика, регламент,
договор — на входе; на выходе список пунктов, которые расходятся с нормой, каждый со ссылкой.
Модель здесь работает с двумя контекстами: фрагмент документа и найденные нормы.

**6. Налоговый календарь из самого кодекса.** Сроки уплаты и представления отчётности разбросаны
по статьям («не позднее 25 числа второго месяца…»). Разовый проход по `chunks.jsonl` с извлечением
таких формулировок даёт календарь, где каждая дата ссылается на пункт-первоисточник.

**7. Карта перекрёстных ссылок.** В корпусе 1 132 связи между статьями. Граф показывает узловые
нормы (на что ссылается всё) и помогает при обучении: «что нужно прочитать вместе со статьёй 190».

**8. Обучающие материалы и карточки.** Заголовки статей плюс тексты пунктов — готовый материал
для тренажёра. `eval/qa-ru.jsonl` показывает формат: вопрос → ожидаемые статьи.

**9. Датасет на Hugging Face.** Parquet по языкам плюс dataset card с теми же лицензиями и
дисклеймером — версия 0.2.0. Таких данных по РК публично нет.

Общее правило для всех сценариев: **ответ без ссылки на статью и пункт бесполезен**. Бухгалтер
не может действовать на основании абзаца без нормы, а проверить неофициальную копию можно только
сверкой с официальным источником — поэтому `source_url` есть у каждой статьи и каждого чанка.

## Модель данных

Одна статья — один файл `code/ru/<часть>/<раздел>/<глава>/st-NNN.md`. Frontmatter даёт фильтры
без парсинга текста: `article`, `heading`, `part`, `razdel`, `glava`, `paragraf`, `path`,
`revision_id`, `effective_from`, `effective_to`, `status`, `cross_references`, `source_url`,
`source_text_sha256`, `text_sha256`. Полное описание полей — [SCHEMA.md](SCHEMA.md).

Внутри статьи каждый пункт адресуем якорем: `code/ru/.../st-190.md#p-3` — это пункт 3 статьи 190.
Чанки нарезаны по той же границе (`chunk_id` вида `kz-tax-code-2025/ru/st-190/p-3`), поэтому
ассистент может дать цитату со ссылкой до пункта, а не «где-то в статье».

### Даты введения в действие

Кодекс введён в действие с 1 января 2026 года (статья 848). Исключения кодируются в
`effective_from` / `effective_note` по тексту той же статьи 848:

## Границы: чего здесь нет

Честные границы важнее полноты обещаний:

- **нет казахской версии** — только русский текст (`lang: ru`); казахская ветка запланирована на 0.2.0;
- **нет подзаконных актов** — приказы, правила и разъяснения КГД сюда сознательно не смешаны;
- **нет истории редакций** — снят один срез; будущие изменения придут коммитами и тегами `revision/*`;
- **нет эмбеддингов** — только текст и полнотекстовый индекс;
- **нет юридической силы** — см. [DISCLAIMER.md](DISCLAIMER.md).

## Известные особенности источника

Всё перечисленное — свойства исходной публикации, а не дефекты сборки; каждое отражено
в `manifest.json → anomalies` и в самих файлах:

- **статья 419 существует в двух экземплярах** (разные идентификаторы источника): `st-419.md`
  и `st-419--2.md`. У второй источник отдаёт пустое тело — файл сохранён с пометкой
  `status: source_empty`, чтобы пропуск нельзя было принять за потерю при выгрузке;
- **у раздела 6** (индивидуальный подоходный налог) в оглавлении источника на месте названия
  стоит пояснительная сноска: номер восстановлен по позиции между разделами 5 и 7,
  `razdel_title` остаётся `null` с флагом `razdel_title_missing_in_source`;
- **20 статей (201–220)** идут в Особенной части до первого раздела — у них `razdel: null`,
  каталог `razdel-00-vne-razdelov`;
- **у 6 статей** (354, 442, 469, 666, 725, 832) заголовок из API источника расходится с оглавлением;
  верным взят заголовок оглавления, расхождение помечено флагом `source_title_mismatch`.

## Оценка качества поиска

В `eval/qa-ru.jsonl` — 53 размеченных вопроса: 12 сформулированы как вопросы бухгалтера и
41 выведен из заголовков статей (по построению лёгкий, нужен как регрессия).
Baseline — обычный BM25 по FTS5, без эмбеддингов и реранкера:

| Набор | recall@1 | recall@5 | recall@10 | recall@20 |
|---|---|---|---|---|
| вопросы бухгалтера (12) | 0.417 | 0.750 | 0.917 | 0.917 |
| выведенные из заголовков (41) | 0.780 | 0.805 | 0.878 | 0.927 |

Это **пол, а не витрина**: цифры показывают, что даёт голый лексический поиск, — и именно
поэтому в примерах выше показан промах на «ставках КПН». Разбор промахов и методика —
[eval/RESULTS.md](eval/RESULTS.md). Векторный прогон появится вместе с эмбеддингами.

## Воспроизводимость

```bash
python3 scripts/build_corpus.py <путь-к-выгрузке>   # выгрузка → code/ru, index.md, manifest.json
python3 scripts/build_chunks.py                     # code/ru → data/chunks.jsonl
python3 scripts/build_sqlite.py                     # chunks → dist/tax.sqlite (FTS5)
python3 scripts/build_llms_txt.py                   # llms.txt
python3 scripts/build_datapackage.py                # datapackage.json
python3 scripts/build_eval_seed.py                  # eval/qa-ru.jsonl
python3 scripts/eval_fts.py                         # baseline-прогон → eval/RESULTS.md
python3 scripts/validate.py                         # 15 проверок целостности; ненулевой код = не публиковать
python3 scripts/ask.py "<вопрос>"                   # ассистент поверх корпуса
```

Только стандартная библиотека Python 3.11+ — ни `pip install`, ни PyYAML не нужны.
`scripts/validate.py` гоняется в CI на каждый PR и сверяет, что `data/chunks.jsonl`
пересобирается из `code/ru` без расхождений.

## Как сообщить об ошибке

Расхождение с официальным текстом — issue с номером статьи и пунктом. Ошибка в разметке
(иерархия, якорь, перекрёстная ссылка) — issue или PR: `scripts/validate.py` должен оставаться зелёным.
